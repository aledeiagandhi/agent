# CMS Debate Kit

제공된 발췌문만을 근거로 `발췌문 → 논제 → 근거카드 → 활동지·루브릭 → 인용 검증`의 연결이 추적 가능한 토론 수업 자료를 만든다.

## 작업 전 확인

1. 현재 폴더와 입력 파일을 읽기 전용으로 조사한다.
2. 발췌문, 토론 규칙, 기존 양식, 사용자 요구를 구분한다.
3. 생성할 산출물, 파일명, 형식, 저장 예정 절대 경로를 먼저 제시한다.
4. 파일 생성·이동·수정은 사용자의 명시적 승인을 받은 범위에서만 실행한다.
5. 입력 발췌문에 문단 번호가 없으면 내용을 바꾸지 않고 인용 식별 방식을 사용자와 정한다. 임의의 문단 번호를 원문 번호인 것처럼 제시하지 않는다.

## 근거 경계

- 발췌문에 없는 내용은 논거, 배경지식, 사실, 사례 또는 인용 근거로 제시하지 않는다.
- 외부 지식으로 빈틈을 메우거나 작품 전체의 내용을 추정하지 않는다.
- 발췌문만으로 판단할 수 없는 항목은 정확히 `발췌문에서 확인 불가`라고 표시한다.
- 불확실한 사실과 수치는 `확인 필요`라고 표시한다.
- 사용자가 외부 자료 조사를 별도로 요청한 경우에도 발췌문 근거와 외부 자료를 명확히 분리하며, 외부 자료를 발췌문 근거처럼 취급하지 않는다.

## 워크플로우

### 1. 발췌문 정리

- 문단 번호, 원문, 핵심 쟁점과 인물·사건의 관계를 확인한다.
- 원문의 표현, 의미, 순서를 임의로 고치지 않는다.
- 토론에 사용할 수 있는 정보와 발췌문에서 확인할 수 없는 정보를 구분한다.

### 2. 논제 설계

- 발췌문 안의 갈등, 판단 또는 선택에서 찬반 논증이 가능한 논제를 만든다.
- 논제가 발췌문만으로 논의 가능한지 확인한다.
- 가치 판단과 사실 판단을 구분하고, 발췌문 밖의 줄거리나 작가 의도를 전제하지 않는다.

### 3. 근거카드 작성

- 각 카드는 주장, 발췌문 근거, 해석, 예상 반론과 재반박이 구분되도록 작성한다.
- 직접 인용은 원문 그대로 옮기고 반드시 문단 번호를 함께 적는다.
- 요약이나 해석을 직접 인용처럼 표시하지 않는다.
- 하나의 인용이 주장을 실제로 뒷받침하는지 설명하고, 연결이 약하면 보완 또는 제외한다.

### 4. 활동지와 루브릭 작성

- 활동지는 논제 이해, 주장, 인용 근거, 설명, 반론, 재반박을 기록할 수 있게 구성한다.
- 루브릭은 발췌문 충실성, 인용 정확성, 주장-근거 연결, 반론 대응, 표현 명료성을 평가하도록 구성한다.
- 평가 기준이 학생에게 관찰 가능한 행동이나 산출물로 드러나게 쓴다.
- 양식이 제공되면 원본을 보존하고 구조와 요구를 우선 따른다.

### 5. 인용 검증

모든 직접 인용을 발췌문과 대조하여 다음을 검사한다.

- 인용문이 글자, 띄어쓰기, 문장부호를 포함해 원문 그대로인지
- 문단 번호가 실제 위치와 일치하는지
- 인용 전후 맥락을 왜곡하지 않았는지
- 주장이 인용으로부터 합리적으로 도출되는지
- 발췌문에 없는 사실이나 추론이 근거로 섞이지 않았는지
- 확인할 수 없는 항목에 `발췌문에서 확인 불가`가 표시되었는지

오류를 발견하면 해당 위치, 오류 유형, 원문 대조 결과와 필요한 수정을 기록한다. 근거가 부족한데도 인용이나 내용을 지어내지 않는다.

## 파일 보호와 저장

- 발췌문, 토론 규칙, 기존 양식 등 원본 파일은 수정, 삭제, 덮어쓰기 또는 이름 변경하지 않는다.
- 새 문서, 코드, 표, 리포트는 작업 대상 루트의 `결과물` 폴더에 저장한다.
- `결과물` 폴더가 없다면 생성 예정 경로를 알리고 승인 후 만든다.
- 파일명 충돌 시 기존 파일을 덮어쓰지 말고 새 파일명을 제안하여 승인받는다.
- 계획에 없던 파일은 건드리지 않는다.

## 완료 보고

완료 후 생성하거나 변경한 파일을 표로 정리하고 다음을 보고한다.

- 파일명과 절대 저장 경로
- 파일별 역할과 변경 내용
- 생성한 파일 수
- 원본이 보존되었는지
- 사용자가 검수할 항목, 특히 인용 원문·문단 번호·주장과 근거의 연결
- 남아 있는 `발췌문에서 확인 불가` 및 `확인 필요` 항목
